ProactiveAgent 技术指南

v0.5.4 · 更新于 2026-08-07

1快速开始

npm 安装（推荐）

# 任意目录，仅需 Node ≥ 18
npm install @proactive-agent/mcp
npx proactive-mcp init
# 自动生成 .mcp.json 挂载配置 + hooks

Windows / Linux / macOS 命令完全一致，无需 curl。三个平台仅需 Node ≥ 18。

手动挂载（任意 MCP 宿主）

{ "command": "npx",
  "args": ["-y", "@proactive-agent/mcp@latest"] }

任何支持 MCP 的客户端（Claude Code / Kimi Code / Cline / Cursor / Windsurf / VS Code / Proma）添加 stdio server 即可。

开发 / 自定义（clone 仓库）

git clone https://github.com/ConradLu2740/ProactiveAgent.git && cd ProactiveAgent
bun install
bun run packages/proactive-mcp/src/index.ts init
💡 挂载后立刻试：以后提交代码前必须先写单元测试再提交 → agent 会自动建议把这条规则写入长期记忆。

2CLI 命令

命令作用
proactive-mcp init一键生成挂载配置 + hooks（可选 --local / --kimi / --force / --dry-run）
proactive-mcp doctor健康检查：配置 / 数据 / hooks / 端口 / 项目身份
proactive-mcp stats记忆与建议统计（观察记忆规模、建议接受率）
proactive-mcp demo教程式示例（隔离数据，--clean 清理）
proactive-mcp migrate0.3.0 数据迁移 / 反向收敛（--merge-to-global / --status / --preview）
proactive-mcp --today启动本地主动中心 Web 面板（端口 PROACTIVE_TODAY_PORT，默认 8737，15s 自动刷新）

3环境变量

Env作用
PROACTIVE_DATA_DIR数据目录（默认 ~/.proma-proactive/，支持绝对路径；以 ~ 开头自动展开用户主目录）
PROMA_MEMORY_DIR兼容旧版数据目录的环境变量（优先读 PROACTIVE_DATA_DIR）
PROACTIVE_PROJECT显式指定项目标识（不设则自动探测 cwd / git remote）
PROACTIVE_TODAY_PORT--today 面板端口（默认 8737，需 1-65535 整数）
PROMA_MEMORY_LLM_DISABLED设为 1 强制关闭 LLM 提取（memory_extract 降级规则模式，零外发）
MEMORY_LLM_*可选：memory_extract 的 LLM 配置（apiKey/baseUrl/model），未配置自动降级规则模式

4MCP Tools（18 个）

类别工具作用
🧠 记忆写入memory_capture显式记住一条（偏好/事实/纠正/流程，立即生效；支持 scope: project/global）
memory_extract把对话交给引擎自动提取（默认待确认，防投毒）
🔍 记忆检索memory_recall关键词/混合检索，任务开始前注入上下文（默认 auto：项目+全局合并；0.5.4 倒排索引）
✅ 记忆闭环memory_pending / confirm / reject待确认记忆 + 行为纠正的确认/拒绝
👤 画像persona_get / persona_save读取合并画像（global base + 项目覆盖）/ 手动保存画像
🔥 场景scene_summary近期热点场景（"你最近在忙什么"）
📊 统计memory_stats记忆系统统计
💡 建议suggest_now / list / accept / ignore主动建议评估 + 反馈闭环（频率学习）
📋 模板daily_review / onboarding_guide每日复盘 / 使用说明

另有 Resources（memory://today、memory://stats、memory://persona）与 Prompts（daily_review、onboarding）。

5Hooks 配置

Claude Code 三层 hooks

Hook触发时机作用
SessionStart会话开始today-push：推送待处理建议 + 热点场景 + 画像摘要
UserPromptSubmit用户发消息时会话中实时评估：你说"以后都用 pnpm"立即收到纠正建议；弱信号自动沉默
Stop会话结束session-end：沉淀记忆 + 评估建议
⚠️ hooks 仅在 Claude Code 交互式 TUI 会话中触发；claude -p 脚本/CI 模式不触发。脚本场景请显式授权：claude -p --allowedTools "mcp__proactive-agent__*"

Kimi Code hooks（主动转述）

Kimi 配置是 TOML（不是 JSON），写在 ~/.kimi-code/config.toml：

[[hooks]]
event = "UserPromptSubmit"
command = "node <mcp 安装路径>/dist/hooks/kimi-user-prompt.js"
timeout = 10

字段只允许 event / matcher / command / timeout。hook 输出 <notification> XML，Kimi 模型看到通知后主动向用户转述建议。

⚠️ Kimi Code 需要先登录或配置 API key（kimi 首次运行 /login，或按 config.toml 配置 [providers.<name>] + api_key）。诊断：kimi doctor / kimi provider list。

6数据目录

~/.proma-proactive/
├── atoms.jsonl        # L1 结构化记忆条目
├── scenes.json        # L2 场景块
├── persona.md         # L3 用户画像（带来源溯源）
├── corrections.json   # 行为纠正候选（需确认生效）
├── projects/<key>/    # 按项目隔离的记忆
├── global/            # 显式共享的全局记忆
└── tasks.json         # 本地任务队列（suggest_accept 落盘）

纯本地文件（JSONL / markdown），可随时备份 / 迁移。推荐用 proactive-mcp stats 观察规模，proactive-mcp archive 做 TTL 归档治理。

7安全与 FAQ

  • 默认 pending：自动提取的记忆需确认才进入召回，阻断投毒链。
  • LLM 同源原则：apiKey 决定主信任源，baseUrl/model 只从同源取；baseUrl 仅 https。
  • 数据本地优先：记忆存在本机，无云同步。
  • 免打扰时段：DND 默认 22:30–08:00 不产生新建议。
  • 克制原则：单次最多 1 条建议、同会话预算限制、"该沉默时沉默"。
  • 性能：0.5.4 起 memory_recall 使用倒排索引，上万条记忆保持低延迟。
  • API key：memory_capture / memory_recall 不需要；memory_extract 可选（未配置自动降级规则模式，零外发）。
